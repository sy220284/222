# 2.1.88 原版全量函数 AST 独立复核（2026-10-31）

## 已独立运行的源码核验

输入为用户私有原版 `claude-code-2.1.88-main(2).zip`（SHA256 `23ee61c936cc73e34dbd556b10ff3ad355d2699a91e4e69cd8fc12791017d33d`），以及 `Claude-Code-2.1.88-全源码逐行复核与复刻规格-最新版.zip`（SHA256 `3b291532059e887b20a9adaf779fb789dabcd843042c5343745f3adfdf372b93`）。

## 已接入统一验收体系

`scripts/source_function_index.py` 读取可信源码哈希和详细规格函数表，逐记录检查路径、所属原文件哈希、行范围、字段和唯一身份；发现同位置多回调时分别保留。`scripts/source_parity_gate.py` 生成可复用函数语义索引，反向检查现有验收契约是否逐条覆盖 20,788 个真实 AST 函数，以及纯常量文件和 vendor 文件级审查。缺失记录写入验收缺口，不会自动变成已通过。

手工升级 `docs/SOURCE_PARITY_CONTRACTS.jsonl` 为 verified 必须再提交原版函数的完整行为描述、对应 Rust 实际入口/文件哈希、测试断言和已通过的 GitHub Actions 提交证据。源码原文仅保留在私有源包，禁止复制到公开仓库。

## 补充：导出值与初始化副作用

原规格另有 `核验数据/export_missed_1212.csv`，独立核对共 **1,212** 个导出变量/常量，分布在 420 个原版文件，逐项核对原文件与代码行号全部存在，且没有重复的文件、行号、名称组合。其中 **481** 条是 `CallExpression` 初始化，可能在加载模块时产生注册、状态变化或其它副作用；原版 AST 函数清单不能替代这些导出值的验收。

统一 `source_function_index.py` 将其纳入 `ExportValue` 复核对象并标记有副作用风险的初始化；实际语义仍需沿初始化表达式和调用链人工及运行验收。它们与 20,788 个函数节点分开计数，禁止把包含导出调用的变量误当成已经审过的函数。

## 独立复核的导出声明去重闭环

再次用原版 TypeScript AST 遍历全部 1,902 个文件中的直接 `export` 变量语句，实际找到 **1,276** 个导出变量节点。与 `export_missed_1212.csv` 按文件、代码行、名称和初始化表达式 AST 类型做逐项比较：**1,212/1,212 记录准确、0 个不存在声明；额外 64 个均为 `ArrowFunction`，已被上面的 20,788 个函数 AST 节点记录覆盖，属于应去重的交叉类型**。故统一功能级索引只增录 1,212 个非函数导出值，并保留 64 个 ArrowFunction 原有函数身份，不把同一行为重复计数。

第一方文件有 87 个没有这六类函数 AST 节点：其中 70 个已由导出值审计对象覆盖，其余 17 个是类型、导出转发、导入或接口用途的文件，须用全文件审计对象继续覆盖。现统一索引原则下：**20,788 个函数/方法 + 1,212 个独立导出值 + 17 个纯文件级对象 = 22,017 个第一方静态审计对象**；另外 4 个 vendor 入口须独立执行文件级复核，总计 **22,021 个定位对象**。这是静态审计单位，绝不将该数量误写为已验收功能数量。

## 已纠正的规格状态写入统计缺陷

使用独立 TypeScript AST 对所有 20,788 个函数节点重新遍历赋值表达式，并按函数嵌套边界排除子函数的赋值，特别检查左操作数以 `STATE`、`this`、`session`、`context` 开头的直接成员赋值。独立扫描有 **495 个函数发生 944 次此类赋值**。与原版规格表的“状态写入数”字段比对，发现 **465 个函数明明发生了 857 次此类赋值，旧统计却为零**。这些是明确的漏报下界，其它变量、Map/Set 方法或跨函数间接状态修改尚未包含。

原版实证：`src/bootstrap/state.ts::regenerateSessionId` 435–450 行直接修改 `STATE.parentSessionId`、`STATE.sessionId`、`STATE.sessionProjectDir`；`switchSession` 468–479 行修改 `STATE.sessionId` 和 `STATE.sessionProjectDir`。旧规格二者均写为零。这个统计字段已在新的 `scripts/source_function_index.py` 改为 `untrusted_original_state_write_count`，并对**所有函数**标记需要原版 AST 与 Rust 运行状态复验；不得把旧数零解释为“函数不会修改状态”，更不得凭该数把功能标成已验收。

该项属于已确认的**规格语义统计错误**，与前述原版代码逐行一致性检查互不冲突：原文正确保留，不意味着概括字段没有漏报。后续应为每条需迁移函数补充真正的状态修改、回滚、恢复及异常契约，并由 CI 绑定实际执行证据。

## 独立复核其它函数语义指标

同一次独立 TypeScript AST 扫描按照函数嵌套边界，重新计算每个函数中的 `ReturnStatement`、`ThrowStatement`、`CatchClause`、`AwaitExpression`，逐项匹配规格包 20,788 条函数记录（含 87 条同位置不同回调的出现顺序），完整结果如下：

| 行为节点 | 原版独立 AST | 规格记录总量 | 逐函数不一致 |
|---|---:|---:|---:|
| 显式返回 | 23,380 | 23,380 | 0 |
| 抛错 | 938 | 938 | 0 |
| 异常捕获 | 1,838 | 1,838 | 0 |
| await | 5,238 | 5,238 | 0 |

因此这四个静态指标暂未发现错误，可以在统一索引中保留为结构线索。**有返回、抛错或 await 的静态节点，并不自动证明 Rust 在实际运行中的行为等价**；真实取消、超时、网络失败、权限和状态一致性继续依赖生产链测试。前述“状态写入数”已确认存在漏报，不能与此处四项混为同一个可靠性结论。
