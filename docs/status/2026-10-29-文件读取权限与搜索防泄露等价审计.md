# 2026-10-29 文件读取权限与搜索防泄露源码级等价审计

## 对照范围与原始证据

原始包：用户提供的 `claude-code-2.1.88-main(1).zip`，直接读取：

1. `src/utils/permissions/filesystem.ts::checkReadPermissionForTool`：在允许工作目录内读取前，先对请求路径和符号链接解析目标执行 **read deny → read ask** 检查；禁止由编辑权限、工作区默认读取权覆盖显式拒绝。
2. `src/utils/permissions/filesystem.ts::matchingRuleForInput`：读取规则以工作目录为根匹配文件路径，`/**` 等目录通配模式参与匹配；原版还包含 Windows/UNC、ignore 规则与多配置来源。
3. `src/tools/FileReadTool/FileReadTool.ts::checkPermissions`：真正调用上述读取权限检查，之后才读取文件内容。
4. `src/utils/permissions/permissions.ts::toolMatchesRule`、`src/utils/permissions/permissionRuleParser.ts`：工具名规则、显式拒绝/询问优先级、内容模式解析。

## Rust 原有差异与修复

- 原 `src/tools.rs::dispatch` 的 `read_file` 直接调用 `read_file`，只检查工作区路径，没有执行 `Read` 显式权限规则；即使用户拒绝读取某个工作区文件，模型仍可直接获取其内容。
- 原 `src/permission_rules.rs::canonical_tool` 没有将 `read_file` 关联到 `Read`；通用 Shell 内容规则不能直接替代文件 glob 权限。
- 原 `search_text`、`grep_files`、`glob_files`、`list_files` 能绕过单文件读取入口访问或列出受限制的文件。

修复提交：

- `69b794795a2c641af6237558307a2c353728738d`：`Read` 名称归一化；使用 `globset` 匹配文件模式，支持同一操作核对请求路径、工作区相对路径和符号链接真实目标；保留 deny > ask > allow。
- `ce0d160ad81e734d41fc1958a02372131dd4c176`：`read_file` 在实际打开文件前执行规则；只读模式仍允许未被拒绝的读取；显式 ask 在无交互模式下拒绝，交互模式需要用户确认。
- `112315ee8d945e0874c1866276c8b76e4d240c91`：`search.rs` 提供逐文件过滤接口，搜索文件内容或列出匹配路径前执行调用方的读取权限判定。
- `9961dd52ac1295e7688ba482402f44af395819dc`：`search_text`、`grep_files`、`glob_files`、`list_files` 接入同一检查；本地技能文件加载同样在读取前检查。
